Pocket Shop — Partner API

Sync your inventory into the Pocket Shop marketplace
v1

Quickstart

One endpoint, one call per product. Send it your catalogue and it stays in sync — call it again with the same reference and it updates instead of duplicating. This exact call works today.

create a product
$ curl -X POST https://mypocketshop.store/api/partner/v1/products/ \
  -H "Authorization: Api-Key psk_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "external_id": "SKU-001",
    "name": "Wireless Mouse",
    "price": "149.99",
    "category_slug": "electronics",
    "stock_quantity": 25
  }'
201 Created
{
  "id": 347,
  "external_id": "SKU-001",
  "name": "Wireless Mouse",
  "price": "149.99",
  "category": { "id": 4, "name": "Electronics", "slug": "electronics" },
  "quality": "new",
  "stock_quantity": 25,
  "is_available": true,
  "image_url": null,
  "created_at": "2026-08-28T22:52:59Z",
  "updated_at": "2026-08-28T22:52:59Z",
  "created": true
}

Run the same call again with a different stock_quantity and you'll get 200 back with "created": false — same product, updated in place. One call per SKU, safe to repeat forever.

Getting a Key

Keys aren't self-served yet — a Pocket Shop admin issues one directly to an approved seller account.

You're an approved seller → Contact Pocket Shop → Key issued, shown once → Use it in every request

Every request needs the key in the Authorization header, using the Api-Key scheme — not Bearer, which is reserved for the mobile app's login sessions:

Authorization: Api-Key psk_your_key_here
Approval is inherited automatically. A key is tied to one seller account. If that account's approval is ever revoked, the key stops working immediately — nothing to do on your end, and nothing you can do to work around it.

The Endpoint

There's exactly one endpoint. It creates or updates depending on whether external_id has been seen before for your account.

MethodPathPurpose
POST /api/partner/v1/products/ Create a product, or update it if external_id already exists for your account
No bulk endpoint yet. Call it once per product. For a full catalogue sync, loop over your inventory and fire one request per SKU — each call is independently safe to retry, which keeps a first integration simple.

Request Fields

  • external_id requiredYour own SKU or product ID. This is the sync key — see Sync Behaviour below.
  • name requiredProduct name shown to buyers.
  • price requiredDecimal string in ZMW, e.g. "149.99".
  • descriptionOptional. Defaults to empty.
  • category_slugOptional. Must match an existing Pocket Shop category — see Categories below.
  • qualityOptional. new · like_new · good · fair · used — defaults to new.
  • stock_quantityOptional integer. Defaults to 0.
  • is_availableOptional boolean. Defaults to true.
  • image_urlOptional. A hosted image URL — no file upload needed.
  • variantsOptional array. Each item needs name, value, sku; optional stock_quantity, is_active.

Sync Behaviour

external_id is scoped to your seller account, not global — use whatever numbering your own inventory system already has.

First call for a SKU

Product created. Response is 201, "created": true.

Every later call, same SKU

Product updated in place — same id, no duplicate. Response is 200, "created": false.

Every field is replaced

An update is a full replace, not a patch — omit a field and it resets to its default. Always send the complete current state of the product.

One exception: variants. Omit it entirely and existing variants are left untouched; send [] to clear them.

Categories

Categories are curated by Pocket Shop, not partner-defined — category_slug has to match one that already exists.

no auth needed
$ curl https://mypocketshop.store/api/products/categories/

Fetch this once, map your own categories onto the closest match, and cache the result — it changes rarely. Leave category_slug out entirely if a product doesn't fit anything existing; it'll simply be uncategorised on Pocket Shop rather than rejected.

Responses

StatusMeaning
201 CreatedNew product — first time this external_id has been seen
200 OKExisting product updated — check "created": false in the body to confirm

Both return the same shape: the full product record plus a created boolean, so your integration can log which happened without a second lookup.

Errors

StatusCauseBody
400Missing required field, or an unrecognised category_slugerrors.category_slug lists valid slugs directly in the message
401Key missing, invalid, revoked, or the seller's approval has lapseddetail names the specific reason
429Rate limit exceeded — see Rate Limits belowStandard throttle response
A 401 on a key you know is correct almost always means the seller account it belongs to isn't approved (or was un-approved). It's not something to retry — contact Pocket Shop to resolve the account, not the request.

Rate Limits

60 requests per minute, tracked per API key — not per seller account, so a second key for the same account (e.g. a staging key) has its own separate budget.

Syncing a full catalogue of a few hundred SKUs comfortably fits in a couple of minutes at this rate. If you're hitting the ceiling on routine syncs rather than a one-off backfill, get in touch — the limit is a starting point, not a hard ceiling.

FAQ

  • Can I delete a product?
    Not yet via the API — set is_available: false on your next sync to hide it from buyers without losing its order history.
  • Can I sync many products in one call?
    Not yet — one request per product. It's a deliberate first version: simpler to integrate against and to retry safely. A batch endpoint is a natural next step once this is proven with real partners.
  • What happens to a product I stop syncing?
    Nothing automatically — Pocket Shop never deletes a product just because it stopped appearing in your feed. Set is_available: false explicitly if you want it hidden.
  • My key stopped working with no code changes on my end.
    Check with Pocket Shop whether the key was revoked or the seller account's approval status changed — both take effect immediately and aren't visible from your side until the next call fails.
